# Lock-in effect preparation and performance gate

`ui3d/lock_effect_preparation.gd` is the shared runtime dispatch and preparation registry. Its keys must match `Wardrobe.EFFECTS`; the audit rejects missing registration/preparation/budgets, including newly added options. Each entry specifies the resource adapter, finite preparation unit count, normal piece quota and reviewed geometry ceiling. A new effect must have an explicit entry rather than inheriting an unlimited budget.

## Runtime behavior

Main installs one preparation node after building the front end. It alternates saved-effect priority with round-robin work on every registered effect during boot/menu time. Each frame performs at most four small units and stops starting work once its 2-ms soft CPU target is reached. An indivisible unit can overrun that target; both individual units and whole preparation frames are measured against the 8-ms gate. Imported models load through ResourceLoader's threaded loader; a temporary off-tree instance primes the exact existing CelPass conversion and is immediately freed. Missing/failed/timed-out loads warn once and become terminal preparation failures; other effects continue. Procedural variants call the existing geometry builders. No hidden bursts, random draws, timers, shadow changes, geometry reductions, or material substitutions are used for preparation.

Script preloading remains part of scene loading, as it was in the previous UI dispatcher. CPU spawn measurements exclude engine boot, imports and script compilation. AtlasPalette uses the existing metadata's exact named sRGB bytes instead of reading the entire texture back; the audit compares every named texel against the atlas PNG after timing, so stale metadata fails validation rather than silently changing colors.

Bills, Dog Toys and Roses use losslessly saved copies of their original procedural meshes under `kit/effects/prepared`. Their background adapter loads one mesh asynchronously, then binds the identical shared cel material. `tests/bake_effect_meshes.gd` regenerates all 48 resources directly from the original builders, strips serialized duplicate materials, reloads every result and verifies exact SHA-256 hashes of the vertex/index/normal/UV arrays. The manifest also fingerprints the source and atlas metadata. The performance audit fails stale/missing/mismatched bakes. Never hand-edit these resources or simplify them to meet budgets. The original builders remain as an authoring fallback; a missing bake is a validation failure, not an acceptable shipping path.

Math's identical shared ShaderMaterial is an explicit preloaded `.tres`. Its first shader-material bind cost about 31 ms on the test GPU and now belongs to initial scene loading, not interactive menu preparation. This is a known startup shader-compilation exception, not a claim that shader compilation is free or included in the 8-ms per-frame preparation gate. Math's 12 cards and Autumn's 24 variants prepare individually. The Math glyph atlas is approximately 6 MiB as uncompressed RGBA8; actual driver VRAM allocation is not measured by the CPU audit.

Preparation pauses during gameplay/results and visible celebrations. Calls that arrive early still execute immediately through the original effect's burst method. They can incur cold work, which is counted in `cold_requests`; they are never dropped, delayed or replayed. This preserves lock-in timing. Preparation and live dispatch mutate caches on the main thread, without yielding inside a cache write. The threaded loader owns only resource loading.

The cache deliberately retains all possible variants for the session, including all 128 Underwear combinations. This trades resident mesh/PackedScene memory for predictable subsequent requests. It does not retain 128 duplicate instantiated node trees. Evicting variants would reintroduce cold loads, so an LRU is not appropriate without a separately approved loading transition. Engine texture/mesh VRAM, driver pipeline caches and allocator overhead are not equivalent to serialized array sizes.

## Reproducible audit

Run `tests/lock_effect_cost_audit.gd` with `--effect=<Wardrobe key> --mode=cold` in a fresh Godot process. Run it again in another fresh process with `--mode=prepared`. Never measure cold effects sequentially in one process: that warms shared atlas/material state. The wrapper `tests/run_lock_effect_audit.py` enumerates Wardrobe, runs both modes serially with a 45-second timeout, and writes JSON plus full logs per effect.

After new assets/scripts land, first run a bounded `--headless --editor --import --quit` pass. `tests/lock_effect_preparation_probe.gd` checks immediate fallback, simultaneous loader/cache access, missing/invalid requests, scheduling fairness and gameplay pause. `tests/customization_probe.tscn` covers saved/menu/match dispatch. `tests/lock_effect_equivalence.tscn` renders original eager wrappers versus prepared caches with isolated fixed-seed script copies; it does not alter production randomness. Its optional GPU timestamp samples describe separate small subviewports in a 14-effect montage, not a full-match GPU budget.

The audit labels the first process burst separately from subsequent bursts. Prepared mode explicitly finishes preparation first, recording preparation CPU cost, maximum indivisible step, frame count, static memory and resource-count deltas. Spawn measurements time only the synchronous burst call; frame waits, mesh inspection and cleanup are outside that timer. Twelve samples exercise random variants; the nearest-rank p95 of 12 is the maximum and should not be mistaken for a statistically stable percentile. Use more samples and repeated runs when investigating a near-threshold result.

It counts nodes, meshes, surfaces, submitted triangles, particle amounts and shadowed mesh instances; separately inventories unique cached meshes/materials/shaders/textures and serialized mesh-array bytes. Three overlapping bursts must coexist and all roots must disappear through their real cleanup timers. Audit-only inventory temporarily instantiates model resources off-tree and frees them immediately.

Current CPU targets: prepared p95 <=4 ms, absolute prepared maximum <=8 ms, one preparation unit <=8 ms. Geometry and serialized mesh storage ceilings are explicit per effect, generally about 5% above measured existing assets; Bills retains a tighter 130,000-triangle ceiling. Node/mesh count ceilings match the existing structures. Winner Confetti has a separate 300-piece/10,300-triangle/8-ms spawn budget. These are reviewed existing exceptions: Bills, Pan and Dog Toys have substantial geometry and must not become defaults for new effects. A failed gate requires investigation and an explicit measured exception with rationale; do not raise every budget or alter approved visuals to make a test green. Headless CPU results **do not measure GPU frame time, shader pipeline compilation, overdraw, texture residency or appearance**. For GPU acceptance, use rendered representative hardware captures with single/three overlapping bursts, compare baseline frame time, and inspect matching before/after visuals. Keep shadows unless rendered evidence establishes equivalence and the visual change is approved.

Future effects must report cold/prepared results, memory costs, per-burst/retained resource counts, cleanup/overlap checks and actual rendered visual review. If a preparation step exceeds its bound, split its resource construction into smaller units or bake an identical approved resource; do not conceal it behind a hidden burst or a monolithic startup prewarm.

## Mandatory first-lock-in audit for new attached/legendary effects (Parker, 2026-11-22)
Before marking a new effect ready or installing it, run fresh-process rendered cold tests in both customization and actual match lock-in, then prepared/repeated tests. Measure synchronous attachment, EVERY asynchronous setup slice, material preparation, first visible frame, and total setup latency separately. Report milliseconds and the slowest operation; a small attach time does not excuse work hidden in later frames. Keep setup slices near 1.5 ms and below the existing absolute 8 ms gate; investigate every overrun. Verify zero runtime GPU mesh/texture readbacks for shipped characters. Use validated CPU geometry bakes/caches and preloaded immutable materials, not get_faces/surface_get_arrays/get_image at first activation. Record unknown-model fallbacks and regenerate bakes after geometry changes.
Capture rendered CPU/frame and GPU baseline versus effect costs, including first draw, single/three concurrent effects and 50 retained characters for persistent effects. Report hardware, resolution, cold versus warm driver-cache limits, and any unmeasured costs; CPU setup timings alone do not prove absence of frame spikes. Check simultaneous setup, the shared >20 legendary LOD threshold, and removal/reselection cleanup. Review visual initialization frame-by-frame for full-size mesh flashes, full-web flashes, unintended material/alpha/outline changes and audio synchronization. Preserve approved visuals and timing. A failed gate stays work-in-progress until fixed or explicitly approved with measured evidence. This requirement applies to all future effects of this kind; retain audit logs and results with each implementation.
